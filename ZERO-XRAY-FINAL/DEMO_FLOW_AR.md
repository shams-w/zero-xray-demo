# ZERO X-RAY — تقسيمة الديمو ببساطة

## 1) Platform Admin
لإنشاء جهة حكومية جديدة وإدارة الاشتراك والحالة العامة فقط.

## 2) Entity Workspace
المساحة الخاصة بالجهة، مثل Emirates Post. الجهة لا ترى بيانات أي جهة أخرى.

### مساحة الخدمة
- نظرة عامة: أرقام سريعة وزر تحليل خدمة جديدة.
- الخدمات: كل خدمة تخص الجهة، وبداخلها سجل التحليلات.
- الخدمات المنشورة: الوكلاء/الخدمات التي تم نشرها ولها رابط عام.

### إدارة الجهة
- مصادر البيانات: الملفات أو المصادر الخاصة بالجهة.
- التكاملات: حالة الربط مع الأنظمة/APIs.
- المستخدمون: موظفو الجهة وصلاحياتهم.
- سجل التدقيق: أهم العمليات التي تمت داخل الجهة.
- الإعدادات: معلومات الجهة والحساب.

## 3) رحلة الخدمة الأساسية
تحليل خدمة جديدة → ZERO X-RAY Analysis → Current Journey → Gap Analysis → Future Journey → Build Agent → Publish Service → Public URL.

## ملاحظة الدخول التجريبي
جلسة الـDemo أصبحت محفوظة في SQLite حتى لا يؤدي إعادة تشغيل/Reload للـbackend إلى تسجيل الخروج تلقائيًا. كما لا يمكن لمدير الجهة إيقاف حسابه الحالي أو تغيير دوره أثناء الجلسة.

## 4) كيف تضيف الجهة بياناتها وتبني Agent قابل للتنفيذ؟
1. **مصادر البيانات**: ترفع/تلصق السياسات، الرسوم، كتالوج الخدمات، المتطلبات، FAQ وملفات PDF/Excel/Word/صور. هذه هي معرفة الوكيل.
2. **التكاملات والأنظمة**: تسجل APIs والأنظمة التي قد يستخدمها الوكيل، وتحدد حالتها: CONNECTED / SANDBOX / NOT_CONNECTED.
3. **إضافة خدمة**: من Services تضغط + إضافة خدمة، ثم تختار مصادر البيانات والتكاملات الخاصة بهذه الخدمة فقط.
4. **Run ZERO X-RAY**: التحليل يقرأ المعرفة المختارة ويعرف الأدوات المتاحة، ولا يفترض وجود تكامل غير مربوط.
5. **Agent Readiness**: في Build Agent تظهر حالة كل تكامل بوضوح: متصل / تجريبي / تكامل مطلوب.

المبدأ: Data Sources = ما الذي يجب أن يعرفه الوكيل؟ Integrations = ما الذي يستطيع الوكيل تنفيذه فعليًا؟
